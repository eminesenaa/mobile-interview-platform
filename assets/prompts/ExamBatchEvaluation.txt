## GENERAL RULES
- `score`: float in [0..5]
- `isCorrect`: true only if answer fully correct (or meets STAR adequacy)
- Empty `user_answer` → `isCorrect=false`, `score=0`, but still return `correctAnswer` and a short `explanation`
- Explanations must be concise (≤2–3 sentences) and in English

---

## TYPE RULES

### 🟩 MCQ (Multiple Choice)
- If `meta["Question Format"] == "MCQ"`, treat as Multiple Choice.
- Accept “A/B/C/D” or full option text (case-insensitive).
- Exact match → `isCorrect=true`, `score=5`; otherwise `false`.
- `correctAnswer` = correct option text.
- `explanation` = brief justification.

---

### 🟦 Fill in the Blank
- Case-insensitive and trim whitespace.
- “False”, “FALSE”, “false” = equivalent.
- Must match expected word(s) exactly unless `acceptedAnswers` provided.
- Partial blanks correct → partial credit (e.g., 2.5 / 3.5 / 4.5).
- `correctAnswer` = ideal correct word or phrase.
- `explanation` = short statement about correctness or missing blanks.

---

### 🟨 Short Answer
- Evaluate factual correctness and conceptual completeness.
- Reward partially correct reasoning (2–4.5 range).
- Focus on key definitions, logic, or steps.
- `correctAnswer` = ideal concise written answer.
- `explanation` = short reason for correctness or key gap.

---

### 🟧 Code Writing
- Non-code or irrelevant → 0
- Logical but incomplete → partial credit
- Fully correct code (syntax + logic) → 5
- `correctAnswer` = minimal canonical code (no comments)
- `explanation` = 1–2 sentences describing main logic or issue

---

### 🟪 Behavioral (STAR)
- Evaluate completeness of S/T/A/R:
  - 5 = Clear S/T/A/R + measurable result/reflection  
  - 4 = Solid S/T/A/R, small gaps  
  - 3 = Partial STAR (≥2 parts)  
  - 2 = Generic or missing key parts  
  - 1 = Off-topic/thin  
  - 0 = Empty
- `isCorrect=true` if ≥3 STAR parts exist (including Action & Result)
- `correctAnswer` = one-line ideal STAR summary
- `explanation` = missing STAR parts or weak result
