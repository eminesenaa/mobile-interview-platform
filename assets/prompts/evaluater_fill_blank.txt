FILL-IN-THE-BLANK — ULTRA COMPACT STRICT SPEC
──────────────────────────────────────────
GENERAL
Applies to all fill-in-the-blank questions.
──────────────────────────────────────────
MANDATORY NORMALIZATION
──────────────────────────────────────────
Before any evaluation, the model MUST for every answer:
• trim whitespace
• convert to lowercase
The normalized value MUST be used everywhere (<user_value> included).
If normalization is skipped or wrong → evaluation is invalid.
──────────────────────────────────────────
SINGLE BLANK (N = 1 — SPECIAL RULE)
──────────────────────────────────────────
If the single blank is correct:
Correct answer.
If the single blank is incorrect:
The correct answer is "<correct_value>". <short_reason>.
Strict rules for SINGLE BLANK:
• Do NOT use “You filled K out of N blanks correctly.”
• Do NOT use per-blank lists
• Output must be short and direct
• <correct_value> must be shown exactly
• <short_reason> must be a brief explanation of the mistake
──────────────────────────────────────────
──────────────────────────────────────────
EVALUATION (MANDATORY ORDER)
──────────────────────────────────────────
Let N = number of blanks.
Normalize all answers
Assign each blank a status: correct or incorrect
Compute K = number of “correct” blanks
score = round((K / N) × 5, 1)
"correct" = true only if K == N, otherwise false
No guessing, no reordering, no early reasoning.
──────────────────────────────────────────
STATUS RULE
──────────────────────────────────────────
For blank i with expected <correct_value_i>:
• Match (or alias) → correct
• Otherwise → incorrect (should be: "<correct_value_i>", because <short_reason>)
──────────────────────────────────────────
REASON RULE (MULTI-BLANK ONLY)
──────────────────────────────────────────
This section applies only when N > 1.
If K == N (ALL correct):
You filled K out of N blanks correctly.
(Exactly one sentence. Nothing else.)

If K < N (ANY incorrect):
You filled K out of N blanks correctly. Per-blank:
1- <user_value> — <status>
2- <user_value> — <status>
...
N- <user_value> — <status>

Strict:
• Exactly N lines
• <user_value> = normalized input
• K must equal number of “correct” statuses
• No extra text
