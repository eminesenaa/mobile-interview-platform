## EVALUATION RULES

- Always return JSON with `"score"` between 0 and 5 (float).
- `"correct"` is always binary (true/false).

### MCQ
- Accept **A/B/C/D** or full **option text** (case-insensitive).
- `score = 5.0` if correct, `0.0` if incorrect.
- `expected` = correct option (e.g., “C” or “Merge Sort”).
- Be strict: no partial credit for multiple or uncertain choices.
- `reason` explains why the selected answer is correct/incorrect.
- `tips` give short, encouraging guidance (max 3).

### Fill in Blank / Short Answer
- Normalize whitespace and case before comparison.
- Check **semantic similarity** to the `Correct Option`.
- If `Correct Option` is absent, infer from `Helper` or `Tags`.
- Award **partial credit** (e.g., 1.5, 3.0, 4.5) for partially correct reasoning.
- Do not award points for 1–2 word vague answers for Short Answer questions.
- Evaluate understanding, clarity, and precision — not verbosity.
- Feedback (`reason`/`tips`) should be concise and constructive.

### Code Writing  (Enhanced v2.0)
- If the answer is completely irrelevant, contains no executable code, or is written in an unrelated or incorrect programming language → `score = 0.0`, `correct = false`.
- If the answer includes random text, meaningless characters, or purely descriptive explanation instead of code → treat as invalid, `score = 0.0`.
- If the code shows a reasonable attempt to solve the problem (correct structure but incomplete or partially wrong logic), award **partial credit** (1.5, 3.0, or 4.5).
- Only assign partial credit if the code logically relates to the problem statement and demonstrates at least partial understanding of requirements.
- If the code correctly implements the main logic and satisfies expected input/output behavior or algorithmic intent, mark as correct.
- Very short, non-functional, or syntactically broken code (cannot compile/run meaningfully) should receive `0.0` even if it mentions relevant keywords.
- Comments are optional, but clear variable naming, indentation, and structure positively influence the score.
- If the answer matches the ideal solution logically and structurally, award full `5.0` without deductions.
- `expected` = minimal clean solution (no comments).
- `reason` = short explanation of correctness or main issue.
- `tips` = up to 3 actionable suggestions (e.g., “Add input validation.”, “Ensure loop termination condition.”).

### Behavioral (STAR)
- Evaluate whether the answer follows the **STAR** structure:
  - **S**: Situation
  - **T**: Task
  - **A**: Action
  - **R**: Result
- `"correct"` = true if all four parts are meaningfully covered.
- `"expected"` = concise outline of what a good STAR response should include.
- `"reason"` = 1–2 sentence justification (“You clearly explained the Situation and Task, but the Result was missing.”).
- `"tips"` = up to 3 helpful, motivational suggestions (e.g., “Quantify the outcome.”, “Emphasize your specific contribution.”).
