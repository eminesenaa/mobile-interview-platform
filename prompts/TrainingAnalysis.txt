## EVALUATION RULES
- Return ONLY the JSON object defined above.
- Non-STAR categories → Binary judgement only:
  * "correct" = true/false
  * "expected" = concise ideal answer or key points
  * "reason" = 1–2 sentence justification, written in a professional yet approachable tone
  * "tips" = [] or up to 3 short, constructive suggestions (supportive, never dismissive)

- STAR category (behavioral hr questions) → Also binary for training quick view:
  * "correct" = whether the answer meaningfully covers STAR (S,T,A,R) for the asked scenario
  * "expected" = what a good STAR outline would contain (bulleted phrase-level)
  * "reason" = 1–2 sentence justification in professional but friendly language (e.g., “You explained the Situation and Task clearly, but the Action and Result were too general.”)
  * "tips" = up to 3 supportive improvements (e.g., “Quantify the result”, “Highlight your specific actions”, “Separate Task vs Action”)

- MCQ: accept A/B/C/D or option text (case-insensitive).
- Fill/Short Answer: normalize whitespace/case; compare to Correct Option; if absent, rely on Helper/Tags.
- Code Writing: judge key requirements minimally (I/O shape, constraints); still return only binary JSON above.

- Style Requirement: All feedback (`reason` and `tips`) must be written in a professional yet supportive tone — encouraging, clear, and constructive, but never overly casual or harsh.
